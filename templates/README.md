# Шаблоны локального каталога питания

Эти CSV-файлы предназначены для первоначального наполнения локальных
справочников продуктов, рецептов, самочувствия, лекарств и БАДов.

Во всех файлах есть строки, идентификаторы которых начинаются с `example_`.
Это только примеры формата: перед импортом удалите их или полностью замените
своими данными.

## Общие правила

- Кодировка файлов — UTF-8, разделитель столбцов — запятая.
- Заголовки менять не следует.
- Десятичный разделитель — точка: `2.5`, а не `2,5`.
- Неизвестное значение оставляйте пустым. `0` означает подтверждённый ноль и не
  должен использоваться вместо «не знаю».
- Штрихкод храните как текст, включая ведущие нули. При открытии CSV в табличном
  редакторе задайте для столбца `barcode` текстовый формат.
- В `aliases` перечисляйте варианты через `;`. Запятые внутри значений должны
  находиться в кавычках.
- Идентификаторы должны быть уникальными и стабильными. Не переиспользуйте
  удалённый идентификатор для другого объекта.
- Рекомендуемые единицы: `g`, `ml`, `piece`, `portion`, `serving`, `tbsp`, `tsp`,
  `cup`, `container`. Для своих единиц используйте одно и то же написание во всех
  файлах.
- Даты записывайте в формате ISO 8601, например `2026-07-27`.

## `foods.csv`

Одна строка описывает один локальный продукт. Значения нутриентов относятся
строго к базе из поля `basis`:

- `per_100g`: `basis_quantity=100`, `basis_unit=g`;
- `per_100ml`: `basis_quantity=100`, `basis_unit=ml`;
- `per_serving`: `basis_quantity=1`, `basis_unit=serving`.

Для `per_serving` заполните фактический размер порции через `serving_quantity` и
`serving_unit`, а также, если известно, `serving_weight_g` или
`serving_volume_ml`. Для баз `per_100g` и `per_100ml` эти поля задают удобную
порцию по умолчанию, но не меняют базу нутриентов.

`density_g_per_ml` нужна только для обоснованного пересчёта между массой и
объёмом. Не подставляйте `1`, если плотность неизвестна.

Числа в столбцах `energy_kcal` … `sodium_mg` записываются без единицы измерения:
она уже указана в имени столбца. Пустой нутриент неизвестен, а не равен нулю.
`source` можно заполнять значениями вроде `manual`, `label`, `open_food_facts`,
`usda` или `import`; в `source_id` сохраняется идентификатор исходной записи.

## `recipes.csv`

Ключ рецепта — пара `(recipe_id, recipe_version)`. При изменении ингредиентов,
выхода или способа приготовления создавайте новую версию, не переписывая старую:
так исторические записи останутся воспроизводимыми.

`yield_quantity` и `yield_unit` описывают итоговый выход готового блюда.
Дополнительно заполните измеренный `yield_weight_g` или `yield_volume_ml`.
`portion_count` — число порций в полном выходе. `default_portion_quantity` и
`default_portion_unit` задают обычную порцию для быстрого ввода.

## `recipe_ingredients.csv`

Каждая строка — один ингредиент конкретной версии рецепта. `line_number` должен
быть уникальным внутри версии. `quantity` и `unit` сохраняют исходное количество;
`weight_g` или `volume_ml` — нормализованное количество для расчёта.

`ingredient_name` хранит понятное человеку название на момент создания рецепта,
а `food_id` ссылается на `foods.csv`. `waste_fraction` — доля несъедобного остатка
от `0` до `1`; оставьте поле пустым, если она неизвестна. `optional` принимает
`true` или `false`.

## `portion_presets.csv`

Пресет связывает разговорное название порции с продуктом или версией рецепта.
Для продукта задайте `target_type=food` и оставьте `target_version` пустым. Для
рецепта задайте `target_type=recipe` и обязательно укажите `target_version`.

`quantity` и `unit` описывают ввод пользователя, а `equivalent_weight_g` или
`equivalent_volume_ml` — подтверждённый эквивалент. В `aliases` полезно указать
голосовые варианты: например `ложка;ст. л.` или `миска;тарелка`.

## `wellbeing_dimensions.csv`

Одна строка задаёт измерение самочувствия: настроение, энергия, стресс или
другое личное измерение.

- `dimension_id` остаётся стабильным после начала использования.
- `aliases` нужны для поиска и будущего голосового ввода, но не меняют label.
- `sort_order` управляет порядком кнопок.
- `is_active=false` скрывает измерение из новых форм, не удаляя прошлые события.

## `wellbeing_options.csv`

Заранее выбранные варианты внутри одного измерения.

- `dimension_id` ссылается на `wellbeing_dimensions.csv`.
- В одном событии можно выбрать максимум одну option каждой dimension.
- Изменение отображаемого label не переписывает snapshot старых событий.
- Начальные примеры намеренно содержат только три градации; при желании их можно
  заменить шкалой из пяти вариантов.

## `medications.csv`

Локальный master list лекарств и БАДов. Это справочник для удобного ввода, а не
назначение и не медицинская рекомендация.

- `item_type`: `medication` или `supplement`.
- `form`: например `tablet`, `capsule`, `powder`, `liquid`, `spray`.
- `strength_value/strength_unit` описывают количество действующего вещества в
  `strength_per_quantity/strength_per_unit`.
- Допустимые единицы зависят от карточки: `mg`, `mcg`, `g`, `ml`, `IU`,
  `tablet`, `capsule`, `dose`.
- Если состав или концентрация неизвестны, поля остаются пустыми.
- `started_on` и `ended_on` — необязательный личный контекст, не schedule.

## `medication_dose_presets.csv`

Обычные варианты фактического приёма.

- `intake_quantity/intake_unit` — сколько форм/объёма принято.
- `active_amount/active_unit` — соответствующее количество действующего
  вещества, если оно известно.
- Изменение preset не меняет сохранённые ранее intake snapshots.
- Доза и единица всегда сохраняются вместе.

## `medication_schedules.csv`

Необязательное расписание для сортировки быстрых кнопок.

- `days_of_week` использует `mon;tue;wed;thu;fri;sat;sun`.
- `time_local` записывается как `HH:MM`.
- `timezone` — IANA timezone.
- Пустые `start_date/end_date` означают отсутствие заданной границы.
- Schedule не является фактом приёма и сам по себе не создаёт
  `medication_intake`.
